# ApplyPilot v1.1 模拟验证与交付记录

日期：2026-09-06。用户未提供新用户样本，本次使用合成候选人、模拟招聘表单与模拟模型响应。验证没有发送真实求职申请或微信消息。

## 1. 无账号安装和使用

### 场景与可行性

没有 ChatGPT / GitHub 账号的用户可匿名获得 ZIP，再手动加载桌面扩展。浏览器仍要求开启开发者模式和选择文件夹。用插件内页面可避开历史托管站点的认证网关。

### 实现

- 扩展新增本机 `options_page`，打包完整工作台和本地依赖。
- 本机档案与旧版云端档案分开存储，提供 JSON 备份与显式迁移。
- 默认不请求云端 API，填表版本需主动选择。
- 用 Node 生成 ZIP 并解压逐文件比对，附 SHA-256。

### 验证

- Chromium、已安装 Chrome、已安装 Edge：合成档案录入、重载恢复、JSON 导出导入、无 API 请求。
- 在独立 Edge 浏览器资料目录实际加载打包后的扩展，验证工作台、弹窗、存储互通及修改后失效。
- Chrome 与 Edge 项目中重复的“扩展加载”测试跳过；整个套件只执行一次扩展加载。
- QQ、夸克没有安装环境，未测试。浏览器商店审核与普通用户手动安装可用性未验收。

### 结论

本机免账号链路通过模拟验证。不是四种浏览器均已认证兼容，也不代表原在线站点已解除托管平台登录。

## 2. 文件转 PDF

### 场景与可行性

照片或已有 PDF 可以在浏览器本机转换与合并；任意二进制文件都无损转成简历 PDF 不可实现。

### 实现

- 实际识别 PNG / JPEG / PDF 文件头，不仅依赖扩展名。
- 图片按比例放入 A4 页面；已有 PDF 复制原页尺寸。
- 总输入和输出各 20 MB、最多 50 页、单图 4000 万像素限制。
- 不支持格式、损坏文件、加密文件明确失败；不会悄悄漏掉失败文件。

### 验证

自动生成 PNG、JPEG 和多页 PDF，转换后用独立 PDF 解析库复读页数与尺寸；测试伪装 PDF、损坏文件、空文件、混合不支持输入、大小和页数超限。

### 结论

PNG、JPEG、PDF 的上述用例通过。OCR、Office 服务端转换、所有相机 EXIF 样本、数字签名保留和所有加密算法未覆盖，不宣称支持任意文件。

## 3. 微信与设备配对

### 场景与可行性

浏览器设备配对和微信公众号身份绑定是两个不同能力。官方公众号主动通知需要运营账号与接口权限；当前没有这些凭据。

### 实现

- 新增 `claim_secret_hash` 数据库迁移。
- 二维码不包含设备领取秘密，设备令牌随机生成、只保存哈希。
- 领取采用条件更新，避免同时发出多个有效令牌。
- 设备档案 API 使用与本机一致的敏感字段过滤。

### 验证

在真实 SQLite 内执行三份迁移并运行 D1 接口适配：仅持二维码、错误秘密、待批准、并发五次领取、重放、过期、撤销。并发只允许一次成功；重放不使已连接设备失效。

### 结论

设备领取逻辑通过本地数据库模拟验证。未执行微信公众号扫码、模板通知、真实官方回调、独立手机号/邮箱注册、跨用户云端全流程验收。旧待领取二维码需要重新生成；迁移应先在测试数据库验收。

## 4. 减少重复填写

### 场景与可行性

桌面网页的可见标准表单可由扩展辅助填写；第三方原生手机 App 没有统一的跨应用填写接口。

### 实现

- 统一档案和结构化 JSON 格式，支持工作台结果直接导入插件。
- 下拉框使用精确选项匹配，避免选空项或把“考虑”匹配成“不考虑”。
- 跳过已有内容，记录插件实际写入值，保留后续手动修改。
- 姓名、英文名、学校和联系方式分别匹配；证件、验证码、声明、文件选择和最终提交不自动处理。

### 验证

在模拟招聘页面运行实际内容脚本；验证普通输入框、下拉框、必填项、预填内容、手改后的第二次填表、文件框和提交计数。全程提交计数为 0。

### 结论

模拟表单通过。未登录真实飞书或 Moka 企业招聘系统；复杂控件、重复经历分组、跨域 iframe 与原生 App 仍需专项适配。

## 5. 直接优化正文并保留原 Word 格式

### 场景与可行性

用户要求得到可直接使用的优化段落，并沿用原简历格式。DOCX 可通过替换正文 XML 中的文字保留原文档资源；PDF 不是同等可编辑结构，无法直接承诺原格式改写。

### 实现

- 上传原 DOCX，提供完整原文与优化稿对照，支持逐段编辑。
- 本机规则精简和模型深度生成明确区分。模型未配置时返回错误。
- 深度生成只接收文本和 JD，要求覆盖原段落编号、保留事实、禁止输出泛泛评价。
- 校验数字、日期及部分职责/熟练度限定词；这些规则不能证明所有语义真实，仍需人工核对。
- DOCX 导出保留其他 ZIP 部件，修改正文文字时保留段落/文字样式、表格属性及节属性。
- 实现独立内容生成 Worker 示例与配置说明，供部署者连接模型服务，终端用户不需要模型账号。

### 验证

- 用含多种字样、表格和节属性的合成 DOCX 对比修改前后 XML。
- 校验正文确实改变，数字及“协助”等限定词未被升级。
- 校验 styles、header、图片等 ZIP 部件字节保持不变。
- 模拟模型返回可直接替换的整段文字，测试响应缺段、错误编号、服务未配置、修改数字和职责夸大。
- 模拟 UI 成功、失败和 DOCX 下载；未调用真实付费模型。

### 结论

DOCX 结构保留与模拟生成链路通过。没有进行 Word / WPS 的像素截图对比，不能保证换行分页完全一致。独立 Worker 的 dry-run 被自动审批额度问题阻止，未完成该 Worker 部署验收。主应用构建已成功，不等于独立 Worker 或真实模型已上线。
