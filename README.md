# 简投 ApplyPilot

维护一份真实档案，按岗位优化简历内容，并辅助填写申请表。支持无需 ChatGPT 或 GitHub 账号的本机工作台。

## v1.2：上传简历、核对档案、导入图片 JD

1. 点击“上传简历并识别主档案”，选择 DOCX 或 PDF（最多 20 MB）。文本 PDF 最多 20 页，扫描 PDF 最多识别 5 页；旧 `.doc` 请在 Word/WPS 另存为 DOCX。中英文 OCR 组件随产品打包，无需填写识别服务地址。
2. 核对自动识别的姓名、联系方式、教育、项目、实习和技能。每项提供原文依据；已有档案字段默认不勾选覆盖。未归类内容会保留在核对区，可修改识别文字后重新解析。
3. 点击“确认所选字段，写入主档案”，完成最后核对。DOCX 会同时载入原格式编辑区，不用再上传一次。PDF 可用于主档案新模板导出，不能据此承诺保留原 PDF 版式。
4. 粘贴岗位 JD，或点击“从图片识别 JD”，选择 PNG/JPEG 图片，核对识别文字后替换 JD。图片最多 20 MB、4000 万像素；低清晰度、多栏阅读顺序、数字与缩写需人工检查。
5. 填写公司和岗位名称，生成岗位版。采购、供应商、订单、入库、GMP 等词已参与匹配和经历排序。关键词提及率不代表筛选通过率。
6. 需要实际深度改写时，在结果区同意发送简历内容并点击“深度改写当前岗位版”。生成结果用于预览与 Word 导出，主档案保持原文；可恢复本机版本。此功能依赖部署方的模型服务，未配置时会明确报错。

文件提取和图片识别在浏览器内执行；首次打开需下载随产品提供的 OCR 静态资源，较旧手机可能较慢。扫描识别置信度不是字段准确率，不承诺任意复杂简历百分之百正确。

## 产品概览

ApplyPilot 面向需要反复修改简历、重复填写招聘表单的求职者。你可以上传原 Word 简历，逐段修改内容并沿用原文件格式导出；也可以填写一次主档案，为多个岗位生成新模板简历、保存投递记录和复用填表数据。

**v1.1 的本机功能无需注册。** 历史在线站点可能仍受托管平台登录限制；没有账号时请使用插件内工作台，或按下面的步骤运行本机网页。手机号/邮箱注册、微信公众号绑定与主动通知仍在开发计划中。

## 功能与优势

| 场景 | 操作与实际结果 |
|---|---|
| 想保留原简历样式 | 上传 DOCX，在原文对照区编辑整段内容，沿用原 Word 的字体、表格、图片、页眉页脚及页边距导出 |
| 需要直接得到优化文字 | 本机精简稿可去除冗词并添加岗位相关标签；部署者配置模型服务后，可按 JD 生成完整替换段落 |
| 每次都要重填个人信息 | 主档案本机保存，一次录入后可重复生成岗位版本、导出 JSON 和选作插件填表数据 |
| 照片需要 PDF | PNG、JPEG 和 PDF 在本机转换、合并为一份 PDF，无需上传服务器 |
| 容易弄混不同岗位简历 | 新模板文件名带公司、岗位和版本号；修改主档案后要求重新生成，历史记录保留原版本 |
| 已手动填过部分表单 | 插件跳过已有内容，保留用户在首次填表后手动修改的值 |
| 不希望交出控制权 | 插件由本人点击后填写；验证码、声明、附件和最终提交仍由本人完成 |

本机精简是规则改写，不能达到语言模型的深度编辑水平。深度改写接口已实现，当前验证使用模拟模型响应；没有配置模型服务时会明确报错，不会假装生成成功。

## 使用前准备

普通用户准备：

- 桌面 Chrome 或 Microsoft Edge。QQ、夸克仅在具体版本允许加载桌面扩展时可能兼容，目前未真机验收。
- 一份真实简历和目标职位描述（JD，至少 40 字）。
- 要保留版式，请准备可编辑 `.docx` 原件；PDF、图片或旧版 `.doc` 需先用 Word / WPS 转为 DOCX 并检查版式。
- 要使用深度改写，请向部署者取得内容生成服务的 HTTPS 地址。普通用户不需要模型服务账号，API 凭据由部署者管理。

## 快速开始：安装插件后直接使用

1. 下载发布版本中的 `applypilot-browser-assistant.zip`。公开仓库的文件可匿名下载：
   [下载安装包](https://raw.githubusercontent.com/vousmetrove/applypilot-ai/main/public/applypilot-browser-assistant.zip)。确认插件详情页版本为 **1.2.0**；若发布链接尚未更新，可使用交付的本地 ZIP。
2. 解压到固定目录，例如 `[你的文档目录]/ApplyPilot/`，应出现包含 `manifest.json` 的 `extension` 文件夹。
3. 打开浏览器扩展管理页：

   | 浏览器 | 地址与操作 |
   |---|---|
   | Chrome | 地址栏输入 `chrome://extensions`，开启开发者模式，选择“加载已解压的扩展程序” |
   | Edge | 地址栏输入 `edge://extensions`，开启开发人员模式，选择“加载解压缩的扩展” |
   | QQ / 夸克桌面版 | 检查当前版本的扩展管理是否提供本地加载入口；没有入口时使用 Chrome 或 Edge |

4. 选择解压后的 `extension` 文件夹，固定简投图标到工具栏。网页无法静默完成安装，这些浏览器操作需要手动执行。
5. 点击插件里的“无需账号 · 打开本机工作台”。无需填写云端地址或扫码。
6. 安装后不要移动或删除插件文件夹。更新前先在工作台导出私人档案备份，再覆盖原插件目录并在扩展管理页点“重新加载”。

从源码加载时，必须先执行 `npm ci` 和 `npm run assets:build`，再加载 **`build/extension/`**。源码中的 `extension/` 不包含构建生成的工作台和依赖文件，不能直接使用。

## 使用方法一：保留原简历格式并优化内容

1. 在“沿用原简历格式，直接改写内容”区域选择原 `.docx` 文件。
2. 在下方“岗位 JD”输入框粘贴完整职责、要求及加分项。不需要再把原文件逐项录入主档案。
3. 检查原文与优化稿对照区。短标题、联系方式以及含特殊对象的段落保留原文；普通正文段落可编辑。
4. 选择生成方式：
   - **生成本机精简稿**：在本机压缩冗余表达、添加与岗位相关的内容标签，无网络调用。
   - **按 JD 深度改写完整内容**：填写部署者提供的内容生成服务地址，勾选全文发送许可，然后点击生成。模型结合章节和全文证据调整求职定位、突出可迁移经历，并返回实际段落，不只是评价或建议。英文简历保持英文；不会把 JD 中的要求当成已有经历。
5. 在右侧直接修改优化稿。重点核对数字、时间、职责范围和技能熟练度；系统的自动检查不能替代事实核对。
6. 点击“沿用原格式下载 Word”，得到 `[原文件名]-岗位优化.docx`。

生成后可展开“查看完整简历正文与导出检查”，连贯阅读整份正文。系统提示改动段数和文字增长较大的段落；每段可单独恢复原文。正文预览不是 Word 版面渲染，仍需检查实际分页。数字、英文职责限定及部分高风险技能词有程序校验，但不能代替人工事实复核。
7. 用 Word / WPS 打开，检查换行、页数、表格和图片位置；需要 PDF 时，在 Word / WPS 选择“另存为 / 导出 PDF”。

此路径在原 DOCX 内替换文字，不新增模板、不调整章节顺序。它保留原文件的排版属性，但内容长度变化仍可能改变换行、分页及部分文字的强调效果。暂不自动改写页眉、页脚、复杂域、带修订的段落或特殊布局对象。原文件只在当前页面内存中处理，刷新后需重新选择；请及时下载优化稿。

## 使用方法二：录入主档案并生成新模板简历

1. 点击右上角“编辑主档案”。填写姓名、联系方式、教育、真实经历、项目和技能。
2. 最高学历可填写本科、硕士、博士等；没有第二段教育或经历时留空，不必编造。
3. 点击“完成编辑”。档案自动保存在当前浏览器，本机模式不会请求云端 API。
4. 填写公司、岗位名称和至少 40 字的 JD，点击“用主档案生成新模板简历”。
5. 查看定向简历正文。关键词提及率只统计词语覆盖，不是 ATS 官方分数、能力鉴定或录用概率。
6. 点击“导出 Word”，或“打印 / 保存为 PDF”。打印对话框中选择“保存为 PDF”，检查预览后保存。
7. 修改档案后重新生成岗位版本。之前的投递记录继续保存生成时的内容。

该路径使用项目自带的新模板；需要原文件样式时请使用上一节的原 DOCX 路径。

## 照片、材料转 PDF

1. 展开“照片 / PDF 转为一份 PDF”。
2. 选择 PNG、JPEG 或 PDF，可多选；合并顺序以文件选择器返回的顺序为准。
3. 点击“转换并下载 PDF”，下载 `applypilot-materials.pdf`。
4. 打开 PDF 检查页序、清晰度、方向和完整性，再手动上传招聘页面。

限制：总输入和输出各不超过 20 MB，最多 50 页，单张图片不超过 4000 万像素。图片放入 A4 页面，PDF 保留原页面尺寸。加密、损坏和不支持的文件会报错，整批失败时不会遗漏部分文件后悄悄导出。PDF 合并不会保留原数字签名效力或完整交互表单，原件应另存。

**不支持“任意格式无损转 PDF”。** Office 文档请先在原软件导出 PDF；压缩包、程序、音视频等不作为简历转换输入。扫描图转 PDF 目前不含 OCR，不能保证招聘系统能提取文字。

## 使用插件辅助填表

1. 在插件工作台完成档案录入；若要使用某个岗位摘要，先生成该岗位版本。
2. 点击“用于本机填表”。网页模式会下载 JSON；在插件内则直接保存到插件存储。
3. 若使用网页下载的 JSON，打开插件的“导入档案 / 岗位 JSON”，选择文件或粘贴结构化结果，点击“仅保存到本机”。
4. 打开招聘申请表，点击简投图标，核对姓名与目标岗位，然后点击“识别并填写当前页面”。
5. 核对绿色标记和缺失提示。插件不自动覆盖已填写内容，也不覆盖上次填表后由你手动修改的内容。
6. 手动处理未识别控件、重复经历分组、跨域 iframe、附件、敏感信息、验证码和声明。
7. 检查后由本人点击招聘网站提交按钮；再在简投“投递进度”中记录状态。

当前使用通用 DOM 标签匹配；模拟表单通过不等于所有飞书、Moka 企业表单都兼容。第三方原生手机 App 和微信内置浏览器不能运行这款桌面扩展。

## 备份、迁移和隐私

- “导出私人档案备份”生成 JSON，包含你填写的个人信息和敏感选填项；请勿公开分享。
- “导入档案 JSON”会在确认后替换当前主档案，保留已有投递记录。备份目前只包括主档案，不包括投递记录、材料和原 DOCX。
- “导入此浏览器旧版档案”用于复制旧版同一浏览器中的档案；不会自动把旧云端账号数据放入游客空间。
- 填表 JSON 和设备 API 会排除证件号、出生日期、紧急联系人等预设敏感字段，以及未分类的自定义问答。自由文本仍可能包含个人信息，导出前请检查。
- 本机数据不跨设备同步。清除浏览器数据、卸载插件或使用隐私窗口可能丢失数据。
- 原 DOCX、图片和本机精简稿默认只在本机处理。深度改写仅在你勾选同意并点击后发送简历全文（含个人信息、章节及只读段落）和 JD；图片及排版资源不会上传。模型服务的数据保留规则由部署者及服务商决定。

详见 [隐私说明](PRIVACY.md)。

## 开发者安装与运行

需要 Git、Node.js **22.13.0 或以上**及 npm。Windows 若拦截 `npm.ps1`，将下面的 `npm` 改为 `npm.cmd`，无需修改系统执行策略。

```bash
git clone https://github.com/vousmetrove/applypilot-ai.git
cd applypilot-ai
npm ci
npm run serve:local
```

打开 `http://127.0.0.1:4174`。该命令先构建插件及浏览器依赖，再启动本机静态工作台；按 Ctrl+C 停止。此服务器不提供云端档案或模型 API。

调试完整应用：

```bash
npm run dev
```

按终端显示的地址访问。`/` 默认进入本机工作台；`/cloud` 是旧版托管认证入口，仍依赖 ChatGPT 身份网关。完整云端功能还需要 D1/R2 和数据库迁移；不要在普通公网服务器直接信任调用者自行设置的 `oai-authenticated-user-id` 请求头。

构建与验证：

```bash
npm run lint
npm test
npx playwright install chromium
npm run test:browser
npm run extension:package
```

`npm test` 构建应用并运行全部 Node 测试，包括档案、PDF、改写契约与 SQLite 配对迁移测试。浏览器测试使用合成候选人与模拟招聘表单，模型响应也采用模拟数据，不发送真实求职申请。

Windows 额外验证已安装的 Chrome 与 Edge：

```powershell
$env:APPLYPILOT_TEST_INSTALLED_BROWSERS="1"
npm.cmd run test:browser
```

安装包位于 `public/applypilot-browser-assistant.zip`，SHA-256 位于同目录 `.zip.sha256` 文件。无需 Linux 的 `zip` 命令。

## 部署者：配置独立内容生成服务

这个服务让最终用户无需 ChatGPT、GitHub 或模型服务账号。**部署者**需要 Cloudflare 账号、支持 Chat Completions JSON 输出的模型 API 凭据，并承担调用费用。以下是部署步骤；当前会话未完成该独立 Worker 的部署和真实模型联调。

1. 完成上述 `npm ci`。
2. 复制配置：

   ```powershell
   Copy-Item wrangler.rewrite.example.jsonc wrangler.rewrite.jsonc
   ```

   macOS / Linux 使用 `cp wrangler.rewrite.example.jsonc wrangler.rewrite.jsonc`。
3. 修改 `wrangler.rewrite.jsonc` 中的 Worker 名称、`RESUME_AI_ENDPOINT` 和 `RESUME_AI_MODEL`。示例端点为 DeepSeek；把 `[your-json-capable-model]` 换成服务商当前支持 JSON 输出的模型名称。`namespace_id` 应使用本 Cloudflare 账号中不冲突的正整数字符串。
4. 登录并设置服务端密钥：

   ```bash
   npx wrangler login
   npx wrangler secret put RESUME_AI_API_KEY --config wrangler.rewrite.jsonc
   ```

   在终端提示时输入密钥。不要写入公开源码或浏览器端。
5. 先验证构建，再部署：

   ```bash
   npx wrangler deploy --dry-run --config wrangler.rewrite.jsonc
   npx wrangler deploy --config wrangler.rewrite.jsonc
   ```

6. 将部署得到的 HTTPS 地址填入工作台“内容生成服务地址”。上传一份合成 DOCX，粘贴测试 JD，允许发送后点击深度改写。
7. 检查返回内容是真实可替换段落，下载并打开 Word；另外测试服务中断、超时、缺段、数字变化等失败提示后，再向用户开放。

服务提供 `POST /api/resume/rewrite`，不处理登录或云端档案。默认按 IP 做每分钟请求限制；共享网络可能共用额度，该限制也不是准确计费上限。上线前应另设模型服务预算与用量告警。接口不会把原 DOCX 的图片或排版文件发送给模型。

实现依据：[Cloudflare Rate Limiting](https://developers.cloudflare.com/workers/runtime-apis/bindings/rate-limit/)、[模型 JSON 输出示例](https://api-docs.deepseek.com/guides/json_mode/)、[Word 文档结构](https://learn.microsoft.com/en-us/office/open-xml/word/structure-of-a-wordprocessingml-document)。

## 常见问题

### 没有 ChatGPT 或 GitHub 账号能用吗？

可以使用插件本机工作台或本机静态网页。历史托管站点的登录限制不影响离线插件。

### 点深度改写提示“尚未配置”怎么办？

请向部署者取得已配置服务的 HTTPS 地址。当前不会用本机规则冒充模型生成。你也可以直接修改右侧段落并导出。

### 原格式导出后页数变了？

文字长度影响换行和分页。压缩右侧文字后重新导出，在 Word / WPS 中检查。系统保留的是原排版结构和属性，未承诺像素级版面一致。

### 插件提示找不到工作台或模块？

如果从源码安装，请先运行 `npm run assets:build`，加载 `build/extension/`。不要直接加载源码 `extension/`。更新后在扩展管理页重新加载。

### 新录入档案后不能填表？

档案修改会使之前选中的填表版本失效。核对后再次点击“用于本机填表”，再打开申请页操作。

### 表单字段没有填写？

插件跳过已有值、无法明确匹配的选项和敏感字段。复杂控件、重复教育分组与跨域 iframe 目前可能需要手填；请使用合成信息反馈复现步骤，不要公开简历。

### 会自动投递或发送微信通知吗？
