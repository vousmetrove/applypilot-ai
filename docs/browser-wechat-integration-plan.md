# 简投 ApplyPilot：多浏览器插件与微信小助手实施方案

## 一、技术原理与整体方案分解

### 1. 总体架构

产品由四个可独立升级的部分组成：

- [简投云端工作台]：保存每位用户独立的主档案、附件元数据、岗位版本、投递状态、设备和活动记录。
- [Manifest V3 浏览器助手]：在用户主动确认后识别当前申请页，匹配飞书招聘、Moka 和通用字段并填写。
- [微信内 H5 小助手]：在微信内查看投递进度、电脑活动，并向已连接电脑发送受控任务。
- [微信官方消息通道]：通过[已认证服务号/小程序/企业微信]接收授权事件、发送订阅消息或客服消息。未获得认证和凭据前，不启用此通道。

数据链路为“主档案 → 岗位 JD 分析 → 岗位专属简历和表单映射 → 浏览器本人确认填写 → 活动回传 → 微信内查看”。每个用户、设备、岗位和附件均按用户身份隔离。

### 2. 跨浏览器兼容原理

扩展采用 Manifest V3、标准 `chrome.storage`、`chrome.scripting`、`chrome.tabs` 和 `chrome.alarms` 能力。Chrome、Edge、QQ 浏览器桌面版和夸克桌面版在支持 Chromium 扩展机制时共用同一源码，只针对商店元数据、图标尺寸、审核说明和能力检测生成不同分发包。

兼容策略如下：

| 浏览器 | 当前安装路径 | 正式分发路径 | 降级处理 |
|---|---|---|---|
| Chrome | 下载 ZIP，开发者模式加载 | [Chrome Web Store 链接] | 无扩展权限时使用复制字段 |
| Microsoft Edge | 下载 ZIP，开发人员模式加载 | [Edge Add-ons 链接] | 无扩展权限时使用复制字段 |
| QQ 浏览器 | 支持扩展管理的桌面版本加载 | [QQ 浏览器扩展中心链接] | 找不到扩展入口时引导 Chrome/Edge |
| 夸克浏览器 | 支持本地扩展或扩展中心的桌面版本加载 | [夸克扩展中心链接] | 移动端直接打开微信 H5 工作台 |

普通网页不能绕过浏览器确认静默安装扩展。因此“一键安装”落地为：点击[统一安装链接] → 自动识别浏览器 → 展示唯一正确入口 → 下载或跳转对应商店 → 用户执行一次“添加/加载”确认。

### 3. 统一分发链接策略

[统一安装链接]读取浏览器 User-Agent 并高亮相应浏览器卡片，给出对应扩展管理地址和步骤。当前可下载已解压安装包；商店审核通过后，仅替换[商店链接]，无需改变用户入口。

邀请链接使用[统一安装链接?invite=邀请码]。邀请码只用于归因和新手引导，不携带主档案、设备令牌或个人信息。任何人点击后都建立自己的账户和数据空间。

### 4. 设备扫码授权原理

扩展首次打开时向云端申请一次性配对记录，云端返回[配对 ID]、8 位[配对码]、[确认链接]和 10 分钟有效期。二维码由简投服务器本地生成，不交给第三方二维码服务。

用户使用微信扫描后：

1. 打开[简投设备连接页]；
2. 未登录时进入[使用 ChatGPT 登录]；
3. 页面展示“这台电脑可读取哪些数据”和明确排除项；
4. 用户点击“确认连接这台电脑”；
5. 电脑扩展轮询到授权状态，换取设备令牌并自动同步主档案；
6. 配对码过期或设备撤销后不能继续使用。

设备令牌只允许访问该用户的档案、上报活动和读取发给本设备的受控任务。令牌以哈希保存；用户可在工作台撤销设备。

### 5. 微信端实时监控接入

第一阶段采用微信内 H5：每 15 秒读取[投递状态]、[浏览器活动]和[已连接设备]，同时支持手动刷新。这部分不依赖个人微信聊天接口，打开链接即可使用。

第二阶段采用微信官方能力：

- 服务号网页授权绑定用户；
- 小程序或服务号订阅消息提醒“投递状态更新、面试安排、档案缺项、电脑任务完成”；
- 用户发送关键词“进度、缺项、设备”时，由官方回调进入规则引擎并生成自动回复；
- 消息窗口或订阅授权不满足官方发送条件时，回退为 H5 待办和站内提示，不进行违规群发。

真实上线第二阶段需要：[已认证微信服务号或小程序]、[AppID]、[AppSecret]、[回调 Token]、[EncodingAESKey]、[备案业务域名]、[JS 接口安全域名]和[订阅消息模板 ID]。

### 6. 自动回复设计

自动回复只处理明确、低风险指令：

| 用户消息 | 自动回复内容 | 是否操作电脑 |
|---|---|---|
| 进度 | 最近岗位及状态摘要 | 否 |
| 缺项 | 当前主档案和申请表缺失字段 | 否 |
| 设备 | 已连接设备和最近在线时间 | 否 |
| 打开岗位 + 链接 | 创建“打开申请页”任务 | 电脑确认后执行 |
| 分析当前页 | 创建“分析当前表单”任务 | 电脑确认后执行 |
| 填写当前页 | 创建“填写当前表单”任务 | 电脑确认后执行 |

涉及密码、验证码、身份证号、承诺声明、附件上传和最终提交时，自动回复统一提示“需要本人在电脑端完成”，不生成绕过路径。

### 7. 远程操作与电脑端部署

“远程操作”不等于开放远程桌面或命令行。云端只允许四类签名任务：同步档案、打开 HTTPS 申请链接、分析当前表单、填写当前表单。扩展每分钟检查一次待办并在图标显示提醒；除档案同步外，均由用户点击“执行”或“拒绝”。

Windows 和 macOS 使用同一个扩展包，不安装常驻系统服务，不申请管理员权限。企业设备策略阻止开发者模式时，改用[浏览器应用商店审核版]；审核前的替代方式为工作台复制字段或导出结构化 JSON。

### 8. 安全与隐私设计

- 不接入非官方个人微信机器人，不模拟微信网页版登录，不读取聊天记录。
- 不保存招聘网站密码，不绕过验证码，不代替用户勾选承诺声明。
- 不自动点击最终提交，不做无人确认的批量海投。
- 敏感字段默认不进入自动填表载荷；证件号继续要求投递时手填。
- 设备配对 10 分钟过期，令牌可撤销，所有活动按用户和设备记录。
- 主档案输入实时保存在本机并延迟同步云端；点击空白处或按 Esc 不关闭编辑窗口。
- 多用户版本不包含任何示例用户的姓名、联系方式、证件或经历数据。

## 二、已经逐项落地的实现

### 1. 主档案与误触保护

- 已包含[硕士主修课程]和[本科主修课程]，并进入 JD 关键词匹配、Word 简历和在线表单字段映射。
- 每次输入立即保存到本机，650 毫秒后同步云端。
- 点击弹窗外空白处或按 Esc 只显示提示，不会关闭；只有右上角“×”和“完成编辑”会关闭。
- “清空档案”需要二次确认。

### 2. 浏览器助手

- 已升级到 Manifest V3 版本 1.0。
- 已实现飞书招聘、Moka 和通用字段文字匹配。
- 已实现硕士/本科课程、求职意向、工作经历、项目、技能、成果等字段识别。
- 已排除密码、身份证、验证码、承诺声明、签名、复选框和最终提交。
- 已实现二维码配对、设备令牌、自动同步档案、设备断开和备用 JSON 导入。

### 3. 实时监控与受控任务

- 已建立设备、设备活动和设备任务三类云端记录。
- 已记录打开申请页、分析表单、本人确认填写和任务完成事件。
- 已在工作台显示最近设备及浏览器活动，并允许撤销设备。
- 已在微信 H5 页面提供每 15 秒刷新、最近投递、电脑活动和四类受控任务。

### 4. 安装与多用户

- 已建立[统一安装向导页]，自动识别 Chrome、Edge、QQ 浏览器和夸克浏览器。
- 已移除前端默认个人姓名和简历资料。
- 数据接口均按登录用户或设备令牌隔离。
- 已保留[浏览器商店链接]占位，需对应商店开发者账号审核后替换。

### 5. 仍受外部条件阻塞的项目

| 项目 | 未完成原因 | 可执行替代方案 |
|---|---|---|
| 微信公众号自动回复 | 缺少认证主体和官方凭据 | 已上线微信内 H5 实时页 |
| 微信订阅/模板消息 | 缺少模板审核和用户订阅授权 | H5 每 15 秒刷新、站内记录 |
| 浏览器商店一键添加 | 需要各商店开发者账号和人工审核 | 已提供统一 ZIP 和逐浏览器引导 |
| 所有飞书/Moka 外部状态自动回写 | 候选人端没有统一公开状态 API | 浏览器事件回传 + 用户手动状态 |
| 无人值守远程桌面 | 安全风险超出求职填表必要范围 | 四类白名单任务 + 电脑确认 |

## 三、非技术用户操作流程

### 1. 插件下载安装

1. 用户点击[统一安装链接]。
2. 页面显示“已识别：[浏览器名称]”。
3. 有商店审核版时跳转[对应应用商店页面]；否则下载[简投浏览器助手 ZIP]。
4. 用户解压到[文档/简投浏览器助手]。
5. Chrome 输入 `chrome://extensions`；Edge 输入 `edge://extensions`；QQ/夸克按页面展示的当前版本入口操作。
6. 开启“开发者模式”，点击“加载已解压的扩展程序”，选择[extension 文件夹]。
7. 看见“简投 ApplyPilot 浏览器助手”卡片即成功；若提示[清单无效]，重新选择包含 `manifest.json` 的文件夹。

### 2. 微信扫码连接

1. 点击浏览器工具栏[简投图标]。
2. 点击“生成手机连接二维码”。
3. 弹窗显示[二维码]、[8 位配对码]和“等待手机确认”。
4. 微信扫码打开[设备连接页]。
5. 未登录时完成[ChatGPT 登录授权]；返回后页面继续保留本次配对。
6. 核对[电脑名称]和权限说明，点击“确认连接这台电脑”。
7. 手机显示“已授权”；电脑在数秒内显示[姓名 · 学校 · 目标岗位]。
8. 若超过 10 分钟，电脑显示“配对已失效”，点击“重新生成”。

### 3. 填写在线简历

1. 打开[飞书招聘/Moka 申请页]。
2. 点击简投扩展。
3. 扩展先同步最新主档案。
4. 用户点击“识别并填写当前页面”。
5. 已填写字段显示绿色轮廓；弹窗列出[已填写数量]、[仍缺必填]和[附件框数量]。
6. 用户检查字段并手动处理附件、验证码、声明和最终提交。
7. 填写结果回传工作台和微信 H5 活动列表。

### 4. 微信内监控和远程任务

1. 用户把[微信端进度页]发送到微信文件传输助手或加入收藏。
2. 页面每 15 秒显示最新岗位状态和电脑活动。
3. 点击“同步档案”“分析当前页”或“填写当前页”创建任务。
4. 电脑扩展图标显示提醒；用户打开后看到任务说明。
5. 用户点击“执行”或“拒绝”。
6. 执行结果回传微信 H5；若电脑离线，任务保持待办，不假装执行成功。

### 5. 自动回复和官方微信接入

1. 管理员准备[认证服务号/小程序]和全部官方凭据。
2. 在微信后台配置[服务器回调 URL]、Token、EncodingAESKey 和业务域名。
3. 云端校验微信签名并解密事件，只接受官方服务器请求。
4. 用户关注或授权后，以 OpenID/UnionID 与简投用户完成一次绑定。
5. 规则引擎按“进度、缺项、设备、打开岗位、分析当前页、填写当前页”回复。
6. 需要操作电脑时创建白名单任务，电脑端继续要求确认。
7. 用户可在[微信授权管理]或[简投设备管理]解除绑定。

## 四、完整用户操作示例

### 用户 A 从 QQ 浏览器安装到微信连接全过程

1. 用户 A 在 QQ 浏览器桌面版点击[统一安装链接]。
2. 页面识别为“QQ 浏览器”，高亮 QQ 卡片，并显示“当前版本需支持扩展管理”。
3. 用户点击“下载适配安装包”，文件保存为[applypilot-browser-assistant.zip]。
4. 用户解压后打开[QQ 浏览器扩展管理页]。若页面存在“开发者模式”，点击“加载已解压扩展”；若不存在，页面提示“该 QQ 浏览器版本不支持本地扩展，请使用 Chrome 或 Edge”，并保留同一下载包。
5. 安装成功后，浏览器工具栏出现[简投图标]。用户点击它，看到“尚未连接”和“生成手机连接二维码”。
6. 用户点击按钮，扩展显示[二维码]、配对码[12345678]和“10 分钟内有效”。若网络断开，显示“无法生成配对码，请检查网络后重试”，不会显示虚假成功状态。
7. 用户用微信扫码。微信打开[简投设备连接页]；由于用户未登录，先进入[ChatGPT 登录页]，授权后返回同一个配对页面。
8. 页面显示电脑名称[QQ 浏览器 · Windows]、可读取范围[主档案]以及不可读取范围[微信聊天、密码、验证码、身份证号]。
9. 用户点击“确认连接这台电脑”。手机显示“已授权，请回到电脑”；扩展轮询到授权后保存设备令牌并同步档案。
10. 如果主档案为空，扩展明确提示“主档案还是空的，请先在简投工作台填写并保存”；用户点击[返回工作台链接]填写姓名、教育、课程、经历和技能，输入过程实时保存。
11. 用户打开[Moka 岗位申请页]并点击简投扩展。扩展先同步最新档案，再由用户点击“识别并填写当前页面”。
12. 页面绿色标记已填写字段，弹窗提示“已填写[数量]项，仍缺[附件/自定义问题]”。验证码、声明和最终提交按钮不被操作。
13. 用户在微信打开[微信端进度页]，看到“Moka · 确认填写 · [时间]”。用户点击“分析当前页”，电脑扩展收到待办提醒；只有用户在电脑点击“执行”后才运行。
14. 用户点击“邀请他人”，转发[统一安装邀请链接]给用户 B。链接不包含用户 A 的档案或令牌；用户 B 登录后建立自己的独立数据空间并重复同样流程。

## 五、验收标准

- 四种浏览器均能在统一入口获得正确说明；不支持时给出明确降级路径。
- 配对码十分钟过期，错误码、过期码和已撤销设备均无法读取档案。
- 两名用户互相不能读取档案、设备、岗位、附件或活动。
- 扩展不会填写密码、证件号、验证码、承诺声明，不会点击最终提交。
- 微信 H5 在微信内可打开，每 15 秒更新且离线时显示真实错误。
- 手机创建的任务必须在电脑扩展中确认，拒绝和失败均有明确状态。
- 主档案误触不会关闭，所有普通字段输入实时保存，课程字段进入 Word 和表单映射。
- 微信官方自动回复和商店安装只有在真实审核、授权和凭据齐备后才标记“已上线”。
